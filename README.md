# DRGS Contracts

DRGS Contracts provides a database of details for [Deep Rock Galactic: Survivor](https://store.steampowered.com/app/2321470/Deep_Rock_Galactic_Survivor/)'s daily [Vanguard Contracts](https://deeprockgalactic.wiki.gg/wiki/Survivor:Vanguard_Contracts) and weekly [Lethal Operations](https://deeprockgalactic.wiki.gg/wiki/Survivor:Lethal_Operations).

Vanguard Contracts (VCs) are daily challenge runs in Deep Rock Galactic: Survivor that lock the player into a specific biome, class, class mod, and starting weapon. VCs may also give players more or fewer weapon slots and may impose restrictions on the weapon pool. Each contract also has mutators, altering how the dive plays, such as slower reloading or increased healing. Lethal Operations (LOs) are also challenge runs, with increased difficulty and a weekly rotation.

The VCs and LOs offered to the player is based on the local system time. The game retrieves the time by the `GetSystemTimeAsFileTime` Windows API time. The TimeHook sub-component detours this API call after initialization, and overrides its return value with a new filetime sent over a named pipe utilized by both halves of the Terminal component.

This project is divided into three logical components:
1. The **Scraper** which is composed of two-subcomponents:
   - The **Terminal** is a console application that injects the TimeHook into the game's process. It opens a handle to the process, writes the DLL's file path into the game's memory, and loads the DLL, which starts its own thread inside the game. The Terminal then prompts the user to choose whether to scrape VCs or LOs and for a date range. For each date, it sends the corresponding filetime to the TimeHook, takes a screengrab of the game, and saves the image to disk for the Extractor to process.
   - The **TimeHook** opens a named pipe on the local system to communicate with the Terminal and detours the `GetSystemTimeAsFileTime` Windows API call, so the game reads the time supplied by the Terminal instead of the system clock.
2. The **Extractor**, which consumes screengrabs generated by the Scraper, extracts the contract details, and outputs them as JSON.
3. The **Webserver** which hosts the user-facing website for looking up VC and LO details.
